# Система планирования путешествия группой

## Назначение
Приложение для планирования совместных путешествий с консольным и веб-интерфейсом Django.
Позволяет работать с путешествиями и участниками: добавлять, искать,
проверять готовность группы к планированию и сохранять данные между запусками.

## Целевая аудитория
- Группы друзей и коллег, которые хотят организовать совместную поездку
- Студенты и молодёжные компании
- Небольшие туристические группы

## Предметная область
Планирование группового путешествия: формирование состава участников,
оценка бюджета, выбор даты начала поездки и проверка возможности её организации.

## Основные сущности
- Путешествие (название, дата начала, бюджет, минимальное число участников)
- Участник группы
- Группа (путешествие + его участники)

## Основные функции
В консольном приложении доступны:

- просмотр и поиск путешествий;
- добавление новых путешествий;
- добавление участников к путешествию;
- проверка, достаточно ли участников;
- проверка готовности группы к планированию;
- сортировка путешествий по бюджету;
- сохранение данных в JSON.

## Основные классы

### Trip — путешествие
- **Атрибуты:** `id`, `name`, `start_date`, `budget`, `min_participants`
- **Методы:**
  - `is_budget_enough(min_budget)` — достаточен ли бюджет;
  - `can_start(current_count)` — хватает ли участников;
  - `__str__()` — строковое представление.

### Participant — участник
- **Атрибуты:** `id`, `name`, `trip` (объект `Trip`)
- **Методы:** `__str__()`

### TravelGroup — группа
- **Атрибуты:** `trip` (объект `Trip`), `participants` (список `Participant`)
- **Методы:**
  - `add_participant(participant)` — добавить участника;
  - `count()` — количество участников;
  - `is_ready()` — готова ли группа к планированию;
  - `__str__()` — строковое представление.

## Взаимодействие объектов
- `Participant.trip → Trip` — участник ссылается на своё путешествие.
- `TravelGroup.trip → Trip` — группа создаётся для путешествия.
- `TravelGroup.participants → [Participant, ...]` — группа хранит своих участников.
- В JSON сохраняются идентификаторы (`trip_id`), при загрузке восстанавливается ссылка на объект `Trip`.

## Хранение данных
Данные хранятся в JSON-файлах в каталоге `data/`:
- `data/trips.json` — путешествия;
- `data/participants.json` — участники.

При загрузке JSON-данные преобразуются в объекты `Trip` и `Participant`,
при сохранении объекты преобразуются обратно в словари.

## Структура проекта
- `main.py` — точка запуска и меню;
- `storage.py` — загрузка и сохранение JSON (с преобразованием в объекты);
- `utils.py` — безопасный ввод чисел и дат;
- `models/` — пакет моделей предметной области:
  - `models/__init__.py` — экспорт классов `Trip`, `Participant`, `TravelGroup`;
  - `models/trips.py` — класс `Trip` и функции работы с путешествиями;
  - `models/participants.py` — класс `Participant` и функции работы с участниками;
  - `models/groups.py` — класс `TravelGroup` (путешествие + участники);
- `data/` — файлы данных:
  - `data/trips.json` — данные о путешествиях;
  - `data/participants.json` — данные об участниках;
- `tests/` — автоматизированные тесты:
  - `tests/test_trips.py` — тесты для класса `Trip` и функций путешествий;
  - `tests/test_participants.py` — тесты для класса `Participant`;
  - `tests/test_groups.py` — тесты для класса `TravelGroup`.

## Веб-интерфейс: ПР5 и ПР6

Django-проект `group_travel` дополняет консольную систему планирования путешествий.
Приложения `homepage`, `trips` и `participants` показывают данные из существующих
JSON-файлов через `storage.py` и классы `Trip`, `Participant`, `TravelGroup`.
ORM, база данных, авторизация и веб-формы пока не используются.
Записи добавляются через `python main.py`.

## Установка и запуск в PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python manage.py check
.\.venv\Scripts\python manage.py runserver
```

Откройте http://127.0.0.1:8000/. Сервер должен оставаться запущенным.
Миграции не требуются. Для остановки нажмите Ctrl+C.

| Страница | URL | Представление |
| --- | --- | --- |
| Главная и статистика | `/` | `homepage.views.index` |
| Список путешествий | `/trips/` | `trips.views.trip_list` |
| Поездка, участники и готовность группы | `/trips/1/` | `trips.views.trip_detail` |
| Список участников | `/participants/` | `participants.views.participant_list` |
| Участник и его поездка | `/participants/1/` | `participants.views.participant_detail` |

Идентификаторы берутся из JSON. Несуществующие записи и адреса возвращают HTTP 404.
Для отсутствующей поездки или участника сайт показывает собственную страницу
с пояснением при любом значении `DEBUG`. Для неизвестного маршрута при
`DEBUG=True` Django показывает диагностическую страницу. Для просмотра
собственного шаблона ошибки остановите сервер и выполните:

```powershell
$env:DJANGO_DEBUG = "False"
.\.venv\Scripts\python manage.py runserver --insecure
```

Проверьте `/trips/999999/`, `/participants/999999/`, `/nonexistent/`.
Параметр `--insecure` используется только локально для раздачи статики без отладки.
После проверки остановите сервер и выполните `$env:DJANGO_DEBUG = "True"`.
Настройки предназначены для локального учебного запуска. При развёртывании
задайте `DJANGO_SECRET_KEY` и настройте обслуживание статических файлов.

## Реализация заданий

ПР5: добавлены `manage.py`, пакет настроек `group_travel`, три Django-приложения,
маршруты через `include()`, динамические пути с числовыми идентификаторами,
представления, пять основных страниц и обработчик `handler404`.
Сохранены консольная версия, классы предметной области, JSON и исходные тесты.

ПР6: итоговая версия использует Django Template Language и `render()`.
HTML находится в шаблонах, функция `page()` в представлениях не используется.

- `templates/base.html`: общий каркас, блоки `title` и `content`, Bootstrap,
  собственные стили, JavaScript и подвал.
- `templates/includes/navigation.html`: общая навигация через `include`.
- `homepage/templates/homepage/`: главная страница.
- `trips/templates/trips/`: список, детали, включаемая карточка и статус группы.
- `participants/templates/participants/`: список и детали участников.
- `templates/404.html`: пользовательская страница ошибки.
- `homepage/static/homepage/`: CSS, изображение `img/logo.svg`, скрипт печати
  `js/main.js`. Кнопка печати находится на странице поездки.

Используются `extends`, `block`, `include`, контекст, `for/empty`, `if`,
фильтры `default`, `length`, `floatformat`, `truncatechars`, `date`.
Ссылки формируются тегом `url` с пространствами имён, ресурсы подключаются через
`static`. Проектные шаблоны находятся через `DIRS`, шаблоны приложений — через
`APP_DIRS`. Bootstrap загружается с CDN; собственный CSS обеспечивает основное
оформление без интернета. Пользовательский текст экранируется Django.
